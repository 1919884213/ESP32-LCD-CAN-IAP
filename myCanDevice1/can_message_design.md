# ESP32-S3 多节点 CAN 报文设计

版本：V1.0  
适用对象：ESP32-S3 仪表主机、STM32 A 运动节点、STM32 B 环境节点、STM32 C I/O 与电源节点

## 1. 总体约定

- CAN 版本：CAN 2.0A
- 帧格式：11 位标准数据帧
- 建议波特率：500 kbit/s
- 数据字节序：小端 Little-Endian
- 周期报文由节点主动发送
- 控制报文由 ESP32-S3 主动发送
- CAN ID 越小，报文优先级越高
- 仅物理总线两端安装 120 Ω 终端电阻

数值字段统一采用整数和缩放因子传输，避免不同 MCU 的浮点格式差异。

## 2. 节点职责

### ESP32-S3 仪表主机

- 接收所有节点数据
- 维护数据缓存和超时状态
- LVGL 界面显示
- 下发 LED、按键、继电器等控制命令
- 通过 CAN 给 STM32 节点发送 IAP 固件

### STM32 A 运动节点

- MPU6050 姿态和加速度采集
- 轮速、编码器采集
- 运动状态和里程计算

### STM32 B 环境节点

- DHT11 温度、湿度采集
- 光敏电阻 ADC 采集
- 发送环境状态报文

### STM32 C I/O 与电源节点

- INA226 电压、电流采集
- ADC 电压采集
- LED、按键、继电器控制

## 3. 报文 ID 分配

```text
0x080              紧急故障
0x100~0x1FF       STM32 A 运动节点
0x200~0x2FF       STM32 B 环境节点
0x300~0x3FF       STM32 C I/O 与电源节点
0x400~0x4FF       ESP32-S3 控制命令
0x600~0x6FF       CAN IAP 升级
0x700~0x7FF       心跳与诊断
```

## 4. STM32 A 运动节点报文

### 0x100：运动状态

发送周期：50 Hz，DLC：8。

```text
Byte 0~1：车速，uint16，单位 0.01 km/h
Byte 2~3：转速，uint16，单位 rpm
Byte 4~5：横滚角，int16，单位 0.01°
Byte 6~7：俯仰角，int16，单位 0.01°
```

### 0x101：三轴加速度

发送周期：50 Hz，DLC：8。

```text
Byte 0~1：X 轴加速度，int16，单位 0.001 g
Byte 2~3：Y 轴加速度，int16，单位 0.001 g
Byte 4~5：Z 轴加速度，int16，单位 0.001 g
Byte 6：运动状态
Byte 7：数据计数器
```

运动状态：

```text
Bit0：静止
Bit1：运动中
Bit2：IMU 数据有效
Bit3：轮速数据有效
Bit4：姿态数据有效
```

### 0x110：轮速和里程

发送周期：20 Hz，DLC：8。

```text
Byte 0~1：轮速，uint16，单位 0.01 km/h
Byte 2~5：累计里程，uint32，单位 0.01 km
Byte 6~7：霍尔脉冲计数，uint16
```

## 5. STM32 B 环境节点报文

### 0x200：DHT11 与光敏电阻数据

发送周期：1 Hz，DLC：8。

```text
Byte 0~1：温度，int16，小端，单位 0.01 ℃
Byte 2~3：湿度，uint16，小端，单位 0.01 %RH
Byte 4~5：光敏电阻电压，uint16，小端，单位 mV
Byte 6：环境状态
Byte 7：数据计数器
```

DHT11 原始数据通常为整数值，因此例如温度 25 ℃传输为 `2500`，湿度 60 %RH 传输为 `6000`。

光敏电阻暂时传输 ADC 换算后的电压，不直接声明为 lux。若要传输照度，需要根据光敏电阻型号、分压电阻和实测照度进行标定。

环境状态：

```text
Bit0：DHT11 数据有效
Bit1：光敏电阻数据有效
Bit2：DHT11 通信超时
Bit3：DHT11 校验和错误
Bit4：ADC 数据无效
Bit5：环境节点 CAN 发送错误
Bit6：热敏电阻数据有效
```

无效数据建议使用以下保留值：

```text
温度：0x8000
湿度：0xFFFF
光敏电阻电压：0xFFFF
```

### 0x201：环境节点诊断

发送周期：1 Hz，DLC：8。

```text
Byte 0：DHT11 连续错误次数
Byte 1：ADC 连续错误次数
Byte 2：CAN 接收错误计数
Byte 3：CAN 发送错误计数
Byte 4：节点运行状态
Byte 5：软件版本
Byte 6~7：运行时间，单位 s，低字节在前
```

### 0x202：热敏电阻数据

发送周期：1 Hz，DLC：8。

```text
Byte 0~1：热敏电阻分压电压，uint16，小端，单位 mV
Byte 2：环境状态（同 0x200）
Byte 3：热敏电阻连续错误次数
Byte 4：数据计数器
Byte 5~7：保留，填 0
```

热敏电阻（NTC）经 ADC2 通道 2（PA2）采样，暂传输 ADC 换算后的分压电压，不直接声明为温度。若要传输温度，需要根据 NTC 标称阻值、B 值、分压电阻及位置进行标定。

## 6. STM32 C I/O 与电源节点报文

### 0x300：电源状态

发送周期：10 Hz，DLC：8。

```text
Byte 0~1：电源电压，uint16，单位 mV
Byte 2~3：电流，int16，单位 mA
Byte 4~5：功率，uint16，单位 W
Byte 6：电源状态
Byte 7：数据计数器
```

电源状态：

```text
Bit0：电源正常
Bit1：欠压
Bit2：过压
Bit3：过流
Bit4：INA226 数据有效
```

### 0x301：ADC 电压

发送周期：10 Hz，DLC：8。

```text
Byte 0~1：ADC0 电压，uint16，单位 mV
Byte 2~3：ADC1 电压，uint16，单位 mV
Byte 4~5：ADC2 电压，uint16，单位 mV
Byte 6：ADC 状态
Byte 7：数据计数器
```

### 0x310：按键与输入事件

仅在输入状态变化时发送，DLC：8。

```text
Byte 0：输入编号
Byte 1：输入状态，0=释放，1=有效
Byte 2~3：全部输入位图
Byte 4~7：事件计数器
```

## 7. ESP32-S3 控制报文

### 0x400：LED 控制

```text
Byte 0：LED 编号
Byte 1：模式，0=关闭，1=常亮，2=闪烁，3=呼吸
Byte 2：亮度，0~100
Byte 3：闪烁周期，单位 10 ms
Byte 4：扩展参数
Byte 5：命令序号
Byte 6~7：保留
```

### 0x401：继电器控制

```text
Byte 0：继电器编号
Byte 1：目标状态，0=断开，1=吸合
Byte 2：保持时间，单位 100 ms
Byte 3：命令序号
Byte 4：控制权限
Byte 5~7：保留
```

### 0x411：控制执行结果

```text
Byte 0：命令类型
Byte 1：命令序号
Byte 2：执行结果
Byte 3：当前输出状态
Byte 4~7：保留
```

执行结果：

```text
0：成功
1：参数错误
2：设备故障
3：权限拒绝
4：执行超时
```

## 8. 心跳与故障报文

### 0x701 / 0x702 / 0x703：节点心跳

分别对应 STM32 A、B、C，发送周期：1 Hz，DLC：8。

```text
Byte 0：节点状态，0=启动中，1=正常，2=降级，3=严重故障
Byte 1：软件版本
Byte 2：CAN 接收错误计数
Byte 3：CAN 发送错误计数
Byte 4：传感器故障位
Byte 5：任务运行状态
Byte 6~7：运行时间，单位 s
```

传感器故障位（STM32 B）：

```text
Bit0：DHT11 故障
Bit1：光敏电阻故障
Bit2：CAN 故障
Bit3：热敏电阻故障
```

### 0x080：紧急故障

发生严重故障时立即发送，DLC：8。

```text
Byte 0：故障节点
Byte 1：故障等级
Byte 2~3：故障代码
Byte 4~5：故障参数
Byte 6：是否锁存，0=不锁存，1=锁存
Byte 7：故障序号
```

故障等级：

```text
0：提示
1：警告
2：严重
3：紧急
```

## 9. CAN IAP 升级报文

IAP 只允许 ESP32-S3 同时升级一个 STM32 节点。固件数据报文使用较低优先级，避免影响实时业务报文。

### ID 分配

```text
STM32 A：0x600 控制，0x610 应答，0x620 数据，0x630 流控
STM32 B：0x601 控制，0x611 应答，0x621 数据，0x631 流控
STM32 C：0x602 控制，0x612 应答，0x622 数据，0x632 流控
```

### 升级命令

```text
0x01：查询节点信息
0x02：开始升级
0x03：发送固件数据块
0x04：结束传输并校验
0x05：激活新固件并复位
0x06：查询升级进度
0x07：取消升级
```

### 开始升级参数

```text
session_id       uint32
firmware_size    uint32
firmware_crc32   uint32
firmware_version uint32
target_address   uint32
```

### 固件数据块

建议每块 256 字节，并通过 ISO-TP 分帧：

```text
block_index uint16
offset      uint32
data_length uint16
data        0~256 字节
block_crc16 uint16
```

### ISO-TP 流控

```text
Byte 0：0x30，允许继续发送
Byte 1：Block Size，建议 8 或 16
Byte 2：STmin，建议 2~5 ms
Byte 3~7：保留
```

### 升级应答

```text
Byte 0：应答命令
Byte 1：状态码
Byte 2：会话序号
Byte 3~4：当前块号
Byte 5~6：错误码
Byte 7：重试次数
```

状态码：

```text
0x00：成功
0x01：准备升级
0x02：接收中
0x03：等待重传
0x04：校验成功
0x05：升级完成
0x80：固件长度错误
0x81：数据块 CRC 错误
0x82：完整固件 CRC32 错误
0x83：Flash 写入失败
0x84：版本非法
0x85：会话超时
0x86：目标地址非法
```

### IAP 安全要求

STM32 应将新固件写入备用 Flash 区域，不能直接覆盖当前运行程序。只有满足以下条件才允许切换启动地址：

```text
固件长度正确
完整 CRC32 正确
版本号合法
向量表地址合法
启动确认成功
```

建议增加 Bootloader 回滚机制，升级后应用程序未在规定时间内发送启动确认时，自动恢复旧固件。

## 10. 接收超时

ESP32-S3 建议按以下规则判断节点状态：

```text
0x100 运动状态：超过 100 ms，数据无效
0x200 环境数据：超过 3 s，环境节点通信异常
0x300 电源状态：超过 300 ms，电源数据无效
0x701~0x703 心跳：超过 3 s，节点离线
```

超时后不能继续把旧数据显示为正常数据，应同时显示“数据无效”或“节点离线”。

## 11. 总线负载建议

- IAP 只升级一个节点
- IAP 数据报文总线占用率控制在 30% 以下
- 保留紧急故障、心跳和电源报文
- 升级期间禁止普通节点同时发送大批量诊断数据
- 业务报文优先级高于 IAP 数据报文
